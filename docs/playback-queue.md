# 播放队列与播放模式

更新：2026-11-04。iOS 与 macOS 共用同一队列模型和持久化格式。

## 使用

- 在歌曲行上长按（Mac 右键）打开菜单，选择“下一首播放”或“稍后播放”。多选歌曲后也可通过“加入队列”批量添加；批量顺序沿用音乐库顺序。
- 添加歌曲不会打断当前播放，也不会自动开始空队列。可以从队列中点击一首歌曲开始。
- 顶部工具栏、底部播放器与完整播放器均可进入队列。队列分为已播放、当前歌曲、接下来三部分。
- 待播部分支持原生列表拖动排序。iOS 从“队列操作 → 调整顺序”进入排序状态；也可用每行菜单中的上移、下移或移到下一首操作。
- 每行菜单可移出单个条目。“清空待播”保留当前歌曲与本轮已播放记录。移除当前条目会停止播放，其余队列保留。
- 队列操作不会删除音乐库文件。同一首歌可以重复加入，每个条目独立排序与移除。

## 模式规则

队列和完整播放器提供“顺序／随机播放”切换及“关闭循环 → 列表循环 → 单曲循环”切换。

随机只打乱待播部分，保留当前歌曲和本轮已播放顺序。关闭随机后，剩余待播歌曲回到原有相对顺序。手动排序会成为新的基准顺序；显式“下一首播放”和“稍后播放”保持本次添加顺序。

上一首沿本轮实际播放顺序回退；播放进度超过 3 秒时先回到当前歌曲开头。自然播完时，单曲循环重复当前条目；手动下一首仍然切歌，到末尾停止。列表循环从队列头开始新一轮，重置上一轮历史；随机列表循环会重新洗牌，多条目时避免相邻两轮首尾为同一条目。关闭循环时，末曲播完停止，保留队列以供重播。

## 保存与恢复

`PlaybackSnapshot` v2 保存独立条目 ID、曲目 ID、基准顺序、已播放／当前／待播顺序、随机状态和随机种子、循环模式及播放进度。编辑、模式切换、暂停、切歌、退到后台时立即保存，播放中每 5 秒检查点保存。意外退出可能丢失最近一次检查点后的进度。

重启恢复为暂停，不自动发声。仅添加但尚未开始的队列，以及空队列上的模式偏好也会保存。旧版保存的曲目 ID 队列会在加载时迁移到 v2。音乐库记录已不存在的条目会从恢复队列移除。

数据库仍有记录、磁盘副本却丢失时，保留该条目便于用户识别：恢复和直接选择它会暂停并显示错误；自动／手动下一首会跳过丢失文件。扫描次数受队列长度约束，列表循环和单曲循环也不会无限重试。全部不可用时停止并提示。文件存在但系统解码失败时停止并显示系统错误，本次不自动跳过解码失败文件。

切歌准备与异步 seek 使用递增请求版本，较早的加载结果不能覆盖较新的选择。准备期间点击暂停会保留暂停意图。

## 验证范围

自动化包含真实音频自然结束后的单曲循环与列表回绕，并覆盖独立重复条目、插入与追加、跨条目选择、排序边界、随机切换、上一首、自然／手动循环语义、快照迁移、丢失文件有界跳过、暂停恢复、快速切歌及音乐库删除回归。UI 回归覆盖队列模式、上移、移出、清空待播与音乐库保留，以及播放中搜索和音乐库管理入口。

测试音频为生成的静音 WAV，测试使用临时音乐库。真机后台、锁屏、蓝牙、耳机拔出及外部音频中断仍需物理设备验收；CarPlay、无缝播放和跨设备同步不在此次范围。
