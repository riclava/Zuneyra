# 本地歌单

更新：2026-11-04。iOS 与 macOS 共用歌单模型、SQLite 存储和播放能力。

## 使用

音乐库新增“歌单”入口，可以创建、重命名、删除歌单。卡片和详情显示封面、歌曲数量与总时长；封面自动使用前四首歌曲的专辑图片，空歌单显示主题占位图。

添加歌曲有四个入口：

- 歌曲行长按／Mac 右键 → 添加到歌单。
- 音乐库多选 → 更多 → 添加到歌单。
- 专辑卡片长按／右键 → 添加到歌单，沿用专辑曲目顺序。
- 歌单详情右上角加号 → 在音乐库中搜索并多选歌曲。

“添加到歌单”窗口可选已有歌单，也可直接新建并加入。重复添加已有歌曲不产生重复条目，同一首歌可属于多个歌单。批量添加沿用音乐库顺序，歌单中已有歌曲保持原顺序。

歌单详情支持原生列表拖动排序，以及歌曲菜单中的上移、下移、移除。iOS 通过“歌单操作 → 调整顺序”进入排序状态。移除歌曲只改变歌单，不删除音频。删除歌单需要确认，也不会删除歌曲或改变当前播放队列。

## 播放

“播放全部”按保存顺序建立新的播放队列，并关闭随机模式。“随机播放”随机选择第一首，再随机安排剩余歌曲。点击歌单中的单曲可从该曲开始顺序播放；以上操作保留当前循环偏好。

“歌单操作”菜单支持将整张歌单插入下一首或追加至队尾。歌曲行也可单独加入队列。

播放时队列复制歌单当时的歌曲顺序。之后改名、调整顺序、移除歌曲或删除歌单均不改变已经建立的播放队列；从音乐库删除歌曲时才会同时清除歌单和队列中的对应引用。

## 存储与升级

SQLite schema 从 v1 迁移到 v2，保留原歌曲、收藏、导入记录和音频。迁移在事务中创建：

- `playlists`：独立 ID、名称、创建和更新时间。
- `playlist_items`：歌单 ID、歌曲 ID、排序位置。

外键在应用的数据库连接中开启：删除歌单清除其成员引用；删除音乐库歌曲清除所有歌单中的对应引用。歌单 ID 与歌曲 ID 联合唯一，位置也在单个歌单内唯一。排序和批量修改在事务中提交，失败回滚完整成员列表与时间戳。应用不会通过旧的整份歌单快照覆盖新内容或重新创建已删除歌单。

名称去除首尾空白后需为 1–100 个字符，不允许控制字符。允许不同歌单使用相同名称，以独立 ID 区分。歌单只保存引用，不额外复制音频。本阶段为每台设备的本地歌单，不包含设备之间同步或导入导出。
