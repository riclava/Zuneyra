# 中文标签与播放中搜索修复

日期：2026-11-04。

## 本地样本分析

只读检查 `mp3 320k` 目录中的 407 首 MP3：378 首带 ID3v2.3 头，29 首没有 ID3v2 头。AVFoundation 读取结果中，25 首存在确定的中文乱码，集中在“2019.11-地表最强世界巡回演唱会 Live”。

这些文件的 ID3v1 文本字段使用 GBK 字节保存中文；系统按 Latin-1 返回了 `ÖÜ½ÜÂ×`、`ÆßÀïÏã` 等字符串，分别应为“周杰伦”“七里香”。正确的 Unicode 标签不需要转换。另一个含不换行空格的正常标签不属于此类乱码。

ID3 文本编码背景参见 [ID3v2.3 规范](https://id3.org/id3v2.3.0)。文件自身标签存在历史兼容问题；不涉及音频解码或 320 kbps 码率。

## 修复策略

- 只读取文件尾部 128 字节的 ID3v1 字段，不改写原文件或托管音频。
- 使用可无损回转的 GB18030 解码，并要求原始艺术家字段提供明确的中文上下文。
- 仅在系统字符串与原始字段的 Latin-1 解释完全一致时替换；有效的 Unicode ID3v2 字段优先保留，西文重音字符不做全局猜测转换。
- 新导入即时修正；旧音乐库加载时按记录版本修正并保存。保留 Track ID、内容哈希、路径、曲序和收藏，播放会话仍按原 ID 恢复。
- 在整批样本上核对，修正 25 首，其余 382 首的系统读取字段保持不变。

这是针对已确认中文旧标签的保守兼容处理，并非任意乱码、所有旧语言编码或已损坏标签的通用恢复工具。

## 搜索栏

原实现使用 `.searchable`，搜索入口位置交由系统导航栏安排，并与底部播放器共享窗口可用区域。现改为音乐库顶部的固定搜索输入框，置于滚动内容之外；播放、暂停、列表滚动和搜索过滤均不移除该输入框。

后续手动验收应在实际开始播放后，检查搜索框仍可点击、可输入且可筛选。原有界面自动化与专用启动参数已移除。

回归测试也暴露了旧的播放时间回调可能覆盖 seek／恢复位置的问题：现使用最新媒体时钟，并在 seek 期间抑制进度回写。

## 历史验证结果

- 全批 407 个本地 MP3 的原始标签与 AVFoundation 输出进行只读比对；兼容处理改变 25 个文件的显示字段。
- iOS 26.5 模拟器：当时的 11 项单元测试通过。
- macOS：当时的 10 项单元测试通过。
- 新增用例确认旧库自动修复后 ID／哈希／收藏不变，音频字节不变；正确 Unicode 标签和西文重音不被误转码。
