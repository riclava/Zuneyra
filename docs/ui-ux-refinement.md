# 音乐库与播放器 UI / UX 优化

更新日期：2026-11-04。面向现有 iOS / macOS 界面，围绕“找到音乐 → 开始播放 → 调整队列”的日常路径改进。该轮沿用暖色视觉、现有音乐库数据和播放会话机制。后续用户选定的极简数字工具视觉见 [当前界面视觉约定](./ui-visual-system.md)。

## 用户问题与实现

| 原有问题 | 本轮实现 |
| --- | --- |
| 手机分类随内容滚走，五个标签被压缩；品牌标题占用首屏 | iOS 分类栏固定在搜索下方，允许横向滚动，保留正常字号与选中状态；使用紧凑导航标题。Mac 保留侧栏。 |
| 专辑内搜索仍显示全库提示，无结果时专辑名称丢失 | 搜索范围明确为“搜索此专辑”，专辑信息独立于筛选结果；无结果提供清除搜索，收藏空态提供浏览歌曲。搜索修剪首尾空白，并匹配歌曲、艺术家、专辑、专辑艺术家和文件名。 |
| 专辑卡片排序正确，但详情与播放上下文沿用入库顺序 | 专辑详情统一使用正数曲号升序，缺失或非正数曲号排在末尾；同曲号按自然标题、文件名及 ID 稳定排序。显示、播放全部及专辑队列操作复用同一顺序。 |
| 列表缺少排序，常用动作依赖长按发现 | 增加最近添加、歌曲名称和艺术家排序；歌曲行显示更多菜单，包含收藏、加入歌单、下一首、稍后播放和删除。长按入口继续保留。 |
| 手机迷你播放器控件过多，曲名可用空间不足 | 默认保留播放 / 暂停与下一首，增加细进度条；点曲目信息进入完整播放器。辅助功能大字号下进一步减少次要控件。Mac 保留上一首、可拖动时间轴和队列入口。 |
| 完整播放器信息层级不清，拖动进度连续触发 seek | 独立 `NowPlayingView` 展示封面、歌曲、艺术家、专辑、时间与主要控制；拖动时预览时间，结束后提交 seek。VoiceOver 可按 10 秒步长调整，iOS 提供系统原生音频输出选择器。 |
| 当前曲目仅以颜色区分；暗色强调文字偏暗 | 当前歌曲增加播放 / 暂停图标和无障碍状态值。区分按钮填充色与深浅色文字强调色，扩大主要交互区域，采用语义字体与适应字号的网格、按钮和文本布局；播放器封面随可用高度缩放，避免窄屏上的主要控制落到首屏之外。 |
| 歌单 / 队列进入排序后，退出方式仍藏在菜单 | 排序时直接显示“完成排序”和拖动提示；列表为空时退出排序状态。歌单空态增加可直接操作的添加入口。 |
| 导入时切到歌单会丢失进度；失败也统一显示完成勾号 | 导入状态提升到共用区域；结果区分完成、重复、部分失败、全部失败和取消，显示对应标题、图标、摘要及重试 / 记录入口。 |

## 维护约定

- `ContentView.swift` 负责导航、搜索范围、专辑展示及歌曲动作；专辑标题来自完整专辑内容，不从筛选结果取值。
- `LibraryPresentation.swift` 集中处理查询和排序。最近添加保留仓储返回顺序；专辑详情不受歌曲列表排序选项影响。当前数据模型没有碟号，本轮没有新增多碟排序能力。
- `MiniPlayerView.swift` 单独订阅播放进度，避免半秒一次的进度更新重建整个音乐库。Mac 与完整播放器复用 `PlaybackTimeline`。
- `NowPlayingView.swift` 使用既有 `PlayerStore` 命令，不创建第二个播放器。进度预览只属于界面状态，切歌时重置。
- `Sunset.coral` 用于白字主按钮填充，`Sunset.accent(_:)` 用于随深浅色变化的文字、图标与 tint。
- 队列和歌单的移除仍遵循原有语义；音乐库删除确认补充说明对所有歌单的影响。

## 历史验证结果

以下为 2026-11-04 修复时的记录，使用隔离的静音测试音乐，未使用用户的实际音乐库。当前仅保留 `ZuneyraTests`；界面自动化用例和专用启动模式已移除，后续界面验收手动进行：

- iOS Simulator 与 macOS Debug 构建通过；`git diff --check` 通过。
- iPhone 17 Pro / iOS 26.5：当时的 53 项单元测试通过。
- `LibraryPresentationTests` 保留 5 项排序与搜索回归，包含曲号的自然排序与搜索字段匹配。
- 人工检查了 375 点窄屏、深浅色、最大辅助功能字号，以及 Mac 播放器和辅助功能进度调整。检查后已恢复原模拟器的浅色与默认字号，并移除临时窄屏模拟器。
- iOS 音频输出选择器接入系统原生控件；蓝牙 / AirPlay 路由切换和完整 VoiceOver 朗读流程尚未进行真机验收。

## 补充修复：macOS 空态弹窗

2026-11-04 用户反馈确认上一轮漏测了 macOS 空队列弹窗。此前构建和播放流程测试通过，不能据此认为空态弹窗的视觉验收也已完成。

- 原因：队列为空时，根 `VStack` 只采用内容的固有高度；有歌曲时 `List` 则填满可用高度。macOS 导航容器在固定尺寸 sheet 内因此产生了不同的布局，连标题栏都被居中推移。
- 修复：队列根容器显式填满并顶部对齐，空态占据剩余内容区。未更改队列数据或播放行为。
- 同类问题：管理弹窗的空导入记录原本仅绘制中间窄列背景；现把空态放在滚动列表外，根背景填满整个弹窗。播放器清空后的空态也使用当前可用高度。导入结果补上导航标题。
- 历史布局检查记录：旧版队列标题距 sheet 顶部 **190.75 点**；修复后标题、内容与关闭按钮保持在弹窗边界内，缩小主窗口后再次打开也通过检查。相关界面自动化用例现已移除。
- 修复时手动查看了播放器内队列由有内容变为空，以及返回播放器后的空态。后续手动验收应覆盖空队列、非空队列、存储页与空历史切换，以及队列排序、移除和清空。
