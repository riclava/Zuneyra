# 第一阶段实现记录

更新：2026-11-04。已按确认的「日落唱片」方向建立原生 SwiftUI 界面。

## 运行

用 Xcode 打开 `Zuneyra.xcodeproj`，选择 `Zuneyra` scheme。选择 My Mac 运行原生 macOS 应用，或选择 iPhone／iPad 模拟器运行 iOS 应用。最低构建目标为 iOS 17、macOS 14；实际最低系统兼容性仍需对应设备验证。真机运行需在 Xcode 配置有效签名。

首次打开为空音乐库。点击“导入音乐”，选择音频文件或文件夹。成功导入后可按专辑、歌曲、艺术家浏览，搜索标题／专辑／艺术家，收藏歌曲。进入专辑后可播放全部或选择单曲；底部播放器支持暂停、上一首、下一首，点击歌曲信息打开完整播放器并拖动进度；队列入口显示当前播放上下文。

两端当前均使用**复制导入**：原文件不移动、不改写。可以删除原位置文件后继续播放应用中的副本。音乐文件保存在应用 Application Support/Zuneyra/Media，音乐库为同目录的 SQLite 数据库。卸载应用前应自行保存原音乐文件；本阶段尚未提供完整备份导出。

## 实现与边界

- 一个 multiplatform app target 编译为原生 iOS 与 macOS 应用，平台条件编译隔离音频会话和桌面布局；应用级 PlayerStore 共享同一进程的播放器。
- MusicRepository actor 负责文件复制、流式 SHA-256 去重、AVFoundation 元数据提取、SQLite 持久化。单文件失败不撤销成功文件，导入结束展示失败明细；取消保留已完成部分。
- 临时文件先进入 Staging，成功解析后移入 Media 并写数据库，失败清理对应副本。重启清理未完成的 Staging 文件。进程在最终移动与数据库提交之间被杀死可能留下未引用的文件；完整导入日志和孤儿文件回收仍属于后续可靠性工作。
- SQLite schema v1 以独立 Track ID 和唯一内容哈希保存可编码元数据；后续规范化艺术家／专辑关系、迁移和复杂歌单时再扩展。不会用文件名判断内容重复。
- 基础播放采用 AVPlayer，使用实际媒体时间更新进度，监听失败、自然结束和播放状态；支持系统媒体命令、iOS 后台音频模式、耳机断开暂停与来电中断策略。
- 使用 UserDefaults 保存当前曲目、队列 ID 和位置，定期与暂停／切歌时检查点保存；重启恢复为暂停，不自动发声。
- 封面读取内嵌图片，按 600 像素生成显示缩略图；缺失封面显示日落风格的本地占位图，不产生网络请求。

本阶段以真实本地文件为内容，没有内置示例音乐。格式筛选包含 MP3、AAC/M4A、ALAC、FLAC、WAV、AIFF，但每个文件仍须通过系统解码检查。当前自动化音频样本为合成 PCM WAV，其他编码、复杂标签和最低系统仍需扩展真机矩阵；不能据此宣称所有编码变体已验证。

## 后续范围

Mac 文件夹引用与授权续期、独立导入任务日志、无缝播放、AVAudioEngine 后端验证、随机／循环、队列编辑、歌单管理、歌词、ReplayGain、备份迁移、CarPlay 不属于本阶段已完成能力。AVPlayer 是基础播放切片的明确选择；专业音频后端按设计文档 M0/M3 另行验证。

后台、锁屏、蓝牙和来电行为已接入系统 API，仍需要物理 iPhone 的长时间播放与路由矩阵验收。模拟器或构建通过不能替代这些验证。
